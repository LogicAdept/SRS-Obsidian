# What is JDBC ResultSet?

> [!abstract] Short answer
> A **`ResultSet`** is a **table of data** for one query result, usually produced by executing a statement. It keeps a **cursor** on the current row. The cursor starts **before** the first row; **`next()`** moves it forward and returns **`false`** after the last row. **Getters** (`getString`, `getInt`, …) read the **current** row by **1-based** index or column label. The **default** set is **`TYPE_FORWARD_ONLY`** and **`CONCUR_READ_ONLY`**. It is **`AutoCloseable`**.

## A cursor over query rows

`java.sql.ResultSet` is “a table of data representing a database result set, which is usually generated by executing a statement that queries the database.” You get one from `PreparedStatement.executeQuery()` / `Statement.executeQuery(sql)`, not from `executeUpdate` ([[How do execute, executeQuery, and executeUpdate differ in JDBC]], [[How are database query results processed in JDBC]]).

Walk it with `while (rs.next())`. The first `next()` that returns `true` makes row **1** current. When `next()` returns `false`, the cursor is **after** the last row; a getter that needs a current row then throws **`SQLException`**. On **`TYPE_FORWARD_ONLY`**, a **further** `next()` after that `false` is **vendor-specified**: another `false` or `SQLException`.

Getters convert the SQL value to a Java type. Column **indexes start at 1**. Labels are **case-insensitive**; duplicate labels return the **first** match — use `AS` or `findColumn`. For portable drivers, read columns **left to right** and **once** per row. After a getter, **`wasNull()`** reports SQL `NULL` (`getObject` returns Java `null` for SQL `NULL`). **`getMetaData()`** returns **`ResultSetMetaData`** (column count, types, properties); those metadata objects stay usable after the `ResultSet` is closed.

## Type, concurrency, holdability

`Connection.createStatement()` (and the matching `prepareStatement` / `prepareCall`) produce result sets that **by default** are **`TYPE_FORWARD_ONLY`** and **`CONCUR_READ_ONLY`**. Holdability is whatever **`Connection.getHoldability()`** returns. Override with the three-int `createStatement` / `prepareStatement` overloads ([[How would you explain ResultSet types scrolling and concurrency modes]]):

| Axis | Constants |
| --- | --- |
| Type | `TYPE_FORWARD_ONLY` — cursor forward only. `TYPE_SCROLL_INSENSITIVE` — scrollable, generally **not** sensitive to underlying changes. `TYPE_SCROLL_SENSITIVE` — scrollable and generally **sensitive**. |
| Concurrency | `CONCUR_READ_ONLY` — may **not** be updated. `CONCUR_UPDATABLE` — may be updated (`updateXxx` then `updateRow`, or the insert row). |
| Holdability | `HOLD_CURSORS_OVER_COMMIT` — stay open on commit. `CLOSE_CURSORS_AT_COMMIT` — close on commit. |

Scroll methods (`previous`, `absolute`, `relative`, `first`, `last`, `beforeFirst`, `afterLast`) need a **scrollable** type. Support for `isBeforeFirst` / `isAfterLast` / `isFirst` / `isLast` / `getRow` is **optional** on `TYPE_FORWARD_ONLY`. A driver that does not support the requested type or concurrency throws **`SQLFeatureNotSupportedException`**. `setFetchDirection` / `setFetchSize` are **hints**; the driver may ignore them.

**Lifetime.** Closing the generating `Statement` — or **re-executing** it, or moving to the **next** result — **automatically closes** the current `ResultSet`. **By default** only **one** `ResultSet` per `Statement` may be open; interleaving two sets needs **two** statements. `close()` on an already-closed set is a no-op. Closing the set does **not** `free()` `Blob` / `Clob` / `NClob` values it created.

```java
import java.sql.Connection;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import java.sql.SQLException;

import javax.sql.DataSource;

public final class WhatIsJdbcResultSet {
    public static Integer quantity(DataSource ds, int id) throws SQLException {
        try (Connection con = ds.getConnection();
             PreparedStatement ps = con.prepareStatement(
                     "SELECT qty FROM article WHERE id = ?")) {
            ps.setInt(1, id);
            try (ResultSet rs = ps.executeQuery()) {
                if (!rs.next()) {
                    return null;
                }
                int qty = rs.getInt(1);
                return rs.wasNull() ? null : Integer.valueOf(qty);
            }
        }
    }
}
```

**Listing 1.** Default forward-only set. `next()` before getters. `wasNull()` after the getter for SQL `NULL`. Nested close so the set dies before the statement.

`Statement.executeQuery` returns a **single** `ResultSet` that is **never `null`**. `execute` may produce a set — then `getResultSet()`. Column metadata is **`ResultSetMetaData`**, not the set itself. `ResultSet` is **not** `java.util.Set`.

> [!warning] Getters need a current row
> The cursor starts **before** row 1. `getString` / `getInt` without a successful `next()` (or `first` / `absolute` on a scrollable set) throw `SQLException`. After `next()` is `false`, there is no current row.

> [!warning] The statement owns the set
> `close`, re-`executeQuery`, or `getMoreResults` on the `Statement` closes the current `ResultSet`. Opening a second set from the **same** default statement closes the first. Keep the `ResultSet` in an inner try-with-resources.

> [!warning] Forward-only is the default, and extra `next()` is vendor-specified
> `previous()` / `absolute()` on `TYPE_FORWARD_ONLY` are not the default contract. After the first `false` from `next()`, another `next()` on a forward-only set may return `false` **or** throw — do not rely on either.

> [!warning] This is not `java.util.Set`
> `ResultSet` does not implement `Set` and is not a collection of unique keys. Do not iterate it like a `HashSet`.

> [!tip] Interview answer
> A JDBC `ResultSet` is a cursor over a table of rows from a query. It starts before the first row, so you call `next()` then getters; columns are numbered from 1. The default is forward-only and read-only, and closing or re-executing the `Statement` closes the current set. After a getter, `wasNull()` tells you if the SQL value was `NULL`.
